# 第 0 回 CAD 図面と 3D アセットを行き来する(全体の見取り図)

> 所要時間の目安: 1 時間 / 前提: Python の基本・NumPy の配列

## この回のゴール

- DXF(CAD 図面)と 3D メッシュを**双方向**に変換するパイプラインの流れを説明できる。
- 各段が**なぜ必要か**(端点のスナップ・隠線判定・文字コード)を、一言で言える。

## 1. 二つの方向

```text
DXF → 自動ルート判定 → 押し出し 3D メッシュ → 屋根 → テクスチャ → Unity / UE
                          ↓(--infer のとき)
                  TripoSR / Zero123++ で外観を推論

OBJ / FBX / GLB → Z バッファで隠線判定 → 三面図 + 平面図 → DXF
```

| 方向 | 入力 → 出力 | 難しさ |
|---|---|---|
| **図面 → 3D** | 建築の平面図(線分の集まり)→ 壁を立ち上げた閉じたメッシュ | 線が**つながっていない**・レイヤー名が**日本語の文字化け**・開口(ドア・窓) |
| **3D → 図面** | メッシュ → 三面図(**見えない線は破線**) | どの辺が**手前に見えるか**(隠線) |

## 2. この講義で学ぶ 3 つの核

| 回 | 核 | 問題 |
|---|---|---|
| [1](01-snap-endpoints.md) | **端点のスナップ**(KD 木 + Union-Find) | 図面の壁の線が、わずかに離れていて、**閉じた壁**にならない |
| [2](02-zbuffer.md) | **Z バッファ**(重心座標のラスタライズ) | 3D の辺のうち、**手前に見える部分**だけを実線にしたい |
| [3](03-encoding-and-capstone.md) | **文字コード**(CP932 と ezdxf の内部表現) | レイヤー名「壁」「建具」を、**文字化けした状態で**照合する |

## 確認問題

1. 図面 → 3D で、線分をそのまま押し出しても、うまくいかないのは、なぜですか。
2. 3D → 図面で、隠線の判定が要るのは、なぜですか。

## 解答

1. 手描きに近い図面では、壁の線の端点が**わずかに離れて**いて、押し出した壁の間に**隙間**ができ、閉じた立体にならない(まず端点をそろえる)。
2. 三面図では、**手前の面に隠れる辺**は、破線にするのが製図の約束。奥行き(深度)を比べないと、見える辺を決められない。

## まとめ

- 双方向の変換。図面 → 3D は「線をそろえて立ち上げる」、3D → 図面は「見える辺を決める」。
- 次の回から、3 つの核を、動かして学ぶ。
