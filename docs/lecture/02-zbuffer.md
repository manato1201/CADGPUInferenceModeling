## この回のゴール

- **Z バッファ**(各ピクセルで、いちばん手前の深さを覚える)の考え方を説明できる。
- 三角形の内側かの判定を、**重心座標**で行う方法を説明できる。

## 1. 隠線とは

三面図では、**手前の面に隠れた辺**を、実線でなく**破線**にします。そのために、「ある辺は、**手前に別の面があるか**」を調べます。

**Z バッファ**は、画像と同じ大きさの**深度マップ**です。

1. 全部のピクセルを「無限に遠い」(`inf`)で初期化する。
2. 三角形を 1 枚ずつ、画面に**塗る**。塗るピクセルの**深さ**を計算し、いま入っている深さより**小さい(手前)**ときだけ、**更新**する。
3. 全部塗り終わると、各ピクセルに、**いちばん手前の深さ**が残る。

辺を調べるときは、「辺の上の点の深さ」と「Z バッファの深さ」を比べ、**バッファのほうが明らかに手前**なら、その点は**隠れている**。

## 2. 重心座標で、内側か・深さはいくつか

三角形の頂点を v0・v1・v2 とすると、内部の点 P は、**3 つの重み**(重心座標 w0・w1・w2。合計 1)で表せます。

```text
P = w0·v0 + w1·v1 + w2·v2        (w0 + w1 + w2 = 1)
```

- **内側**なら、3 つの重みが**すべて 0 以上**。
- 深さは、**同じ重みで補間**できる: `depth = w0·d0 + w1·d1 + w2·d2`。

```python
# 引用: core/mesh_to_dxf.py::_rasterize_faces
@numba.njit(cache=True)
def _rasterize_faces(px_h, px_v, pts_d, faces, size):
    """
    三角形群をZバッファへラスタライズする（numba nopythonモードでJITコンパイル）。

    数学的アルゴリズム（重心座標によるカバレッジ判定・深度更新条件）は
    元のnumpyベクトル化実装（np.meshgrid + ブールマスク）と完全に同一で、
    三角形ごと・ピクセルごとのネストしたforループに書き換えただけである。

    注意: njit関数は初回呼び出し時にJITコンパイルされるため、初回のみ
    数秒のウォームアップオーバーヘッドが発生する（2回目以降は cache=True
    によりディスクキャッシュされたネイティブコードが再利用され高速）。
    ベンチマーク計測時はこのウォームアップ込みの初回と、ウォームアップ後の
    実行時間を分けて見るとよい。
    """
    z_buf = np.full((size, size), np.inf, dtype=np.float32)
    n_faces = faces.shape[0]

    for fi in range(n_faces):
        a = faces[fi, 0]
        b = faces[fi, 1]
        c = faces[fi, 2]
        h0 = px_h[a]; h1 = px_h[b]; h2 = px_h[c]
        v0 = px_v[a]; v1 = px_v[b]; v2 = px_v[c]
        d0 = pts_d[a]; d1 = pts_d[b]; d2 = pts_d[c]

        # バウンディングボックス
        xmin = max(0,      int(min(h0, h1, h2)))
        xmax = min(size-1, int(max(h0, h1, h2)) + 1)
        ymin = max(0,      int(min(v0, v1, v2)))
        ymax = min(size-1, int(max(v0, v1, v2)) + 1)
        if xmin >= xmax or ymin >= ymax:
            continue

        # バリセントリック座標でピクセルをカバー
        area = (h1-h0)*(v2-v0) - (h2-h0)*(v1-v0)
        if abs(area) < 0.5:
            continue

        for py in range(ymin, ymax):
            gy = np.float32(py)
            for px in range(xmin, xmax):
                gx = np.float32(px)
                w0 = ((h1-h2)*(gx-h2) + (v2-v1)*(gy-v2)) / area
                w1 = ((h2-h0)*(gx-h0) + (v0-v2)*(gy-v0)) / area
                w2 = 1.0 - w0 - w1
                if w0 >= -0.01 and w1 >= -0.01 and w2 >= -0.01:
                    depth = w0*d0 + w1*d1 + w2*d2
                    if depth < z_buf[py, px]:
                        z_buf[py, px] = depth

    return z_buf
```

読み方:

- 各三角形について、**バウンディングボックス**(囲む長方形)の中のピクセルだけを調べる(全画面は調べない)。
- `area` は、三角形の**符号つき面積の 2 倍**。0 に近い(**ほぼ線に潰れた**)三角形は、飛ばす。
- 判定は `w >= -0.01`: **ほんの少し外側**まで許す(**縁のピクセルの取りこぼし**を防ぐ許容)。
- `depth < z_buf[py, px]` のときだけ更新(**手前を残す**)。

## 3. なぜ numba か

ピクセルごとの二重ループは、**純粋な Python では遅い**(大きなメッシュで数十秒)。`@numba.njit` は、最初の呼び出しで**機械語にコンパイル**し、以降は C に近い速さで動きます(`cache=True` で、コンパイル結果をディスクに保存)。

- 初回だけ、**数秒のウォームアップ**がある(ベンチマークでは、初回とその後を分けて見る)。
- 中では、**NumPy と単純なループだけ**を使える(`nopython` モード)。

```python
# 実行できる
import numpy as np

from core.mesh_to_dxf import _build_zbuffer

# 同じ向きに、大きな三角形(深さ 5)と、手前の小さな三角形(深さ 2)を重ねる
verts = np.array([[0, 0, 5], [10, 0, 5], [0, 10, 5],      # 奥の大きな三角形
                  [0, 0, 2], [4, 0, 2], [0, 4, 2]], dtype=float)   # 手前の小さな三角形
faces = np.array([[0, 1, 2], [3, 4, 5]])

z_buf, params = _build_zbuffer(verts, faces, ax_h=0, ax_v=1, ax_d=2, size=16, margin=0.0)
values, counts = np.unique(z_buf, return_counts=True)
for value, count in zip(values, counts):
    label = "未描画(inf)" if np.isinf(value) else f"深さ {value:g}"
    print(f"{label:12} {count:3d} ピクセル")
print("画面の左下付近(手前の三角形の上):", z_buf[14, 1], "/ 右へ寄った所(奥だけ):", z_buf[10, 8])
```

```text
# 出力
深さ 2          15 ピクセル
深さ 5         105 ピクセル
未描画(inf)     136 ピクセル
画面の左下付近(手前の三角形の上): 2.0 / 右へ寄った所(奥だけ): 5.0
```

**手前の三角形(深さ 2)がある所では 2、奥の三角形だけの所では 5、どちらも無い所は `inf`** になります。ピクセルの数は、三角形の面積に**ほぼ**比例します(縁の許容 `-0.01` で、少しずれる)。

## 確認問題

1. Z バッファで、塗る順番を変えても、結果が同じなのは、なぜですか。
2. 重心座標の 3 つの重みが、すべて 0 以上なら、点はどこにありますか。
3. 面積が 0.5 未満の三角形を飛ばすのは、なぜですか。
4. 最初の呼び出しだけ遅いのは、なぜですか。

## 解答

1. 各ピクセルで、**深さの最小値**を取るだけだから(順序に依らない)。
2. 三角形の**内側(または辺の上)**。
3. ほぼ線に潰れた三角形は、重心座標の計算で**ゼロ割りに近く**なり、結果が不安定になる。描いても、ほとんどピクセルを覆わない。
4. `numba` が、最初の呼び出しで**機械語にコンパイル**するから(2 回目以降は、キャッシュを使う)。

## まとめ

- Z バッファ = ピクセルごとに**最小の深さ**を残す深度マップ。隠線は「辺が、バッファより奥か」で決まる。
- 内側判定と深さの補間は、**重心座標**。縁には、小さな許容を付ける。
- `numba.njit` で、二重ループを高速化(初回はコンパイルのため遅い)。
